# ADR-0010 — The blocklist is about hosts, so its sources must be too

**Дата:** 2026-08-13
**Статус:** принято

## Контекст

До этого решения в проде лежал фид из четырёх `.test`-доменов. Механизм работал
и не защищал никого: гейты были зелёными про список, который не блокировал
ничего настоящего.

Расширение блокирует **по хосту** — правила `declarativeNetRequest` из
`||host^`, потолок 5000 (`packages/core-feeds/src/rules.ts:RULE_LIMIT`). Это не
деталь реализации, а то, что решает, какие источники вообще пригодны.

`docs/data-sources.md` называет три бесплатных кандидата: OpenPhish community,
URLhaus (abuse.ch) и агрегат Phishing Army. Все три доступны без ключа —
проверено запросом 2026-08-13.

## Решение

**Источник один: OpenPhish community.** URLhaus и Phishing Army не подключаются.

### Почему не URLhaus — и это главное

URLhaus перечисляет **URL**, по которым лежит зловред, а не хосты, которые
зловредны. Третья строка загрузки — ссылка на `dropbox.com`.

Измерено на скачанном списке 2026-08-13: **63 978 строк, 6030 различных
хостов**, из которых **11 — сервисы, которые нельзя блокировать целиком**:
`www.dropbox.com`, `github.com`, `raw.githubusercontent.com`,
`firebasestorage.googleapis.com`, `drive.google.com`, `sites.google.com`,
`gitlab.com`, `mediafire.com` и ещё три.

Подключить URLhaus на нашей гранулярности — значит выключить GitHub и Google
Drive у каждого, кто поставил расширение. Зловред на общем хостинге — факт про
URL, а не про хост, и продукт не может действовать на этом факте, пока у него
нет механизма уровня пути. Такого механизма нет.

### Почему не Phishing Army

Кумулятивный агрегат: 600k+ доменов, 3.2 МБ, без дат. Потолок — 5000. Взять
5000 из 600k без признака свежести — не отбор, а подбрасывание монеты с числом
сбоку.

### Почему OpenPhish

~250–300 живых фишинговых URL, обновление примерно раз в 12 часов, у каждого —
хост, поднятый под кампанию. Это ровно та форма, которую хочет хостовый
блок-лист под жёстким потолком: свежая, небольшая и про хосты, а не про пути.

## Две защиты, без которых это решение не работает

1. **Список «никогда не блокировать целиком»** — общие хостинги и публичные
   суффиксы. Совпадение точное: `vercel.app` отвергается, `evil.vercel.app`
   проходит, потому что второе — хост одной кампании и не задевает никого.
2. **Двухметочный хост короче восьми символов отвергается как сокращатель.**
   Первый же настоящий прогон выдал `g5.lu`, `goo.su`, `s4w.in`, `i.gal` и
   `vo.la` — ни одного не было в списке, все пять сокращатели. OpenPhish
   сообщает хост сокращённой ссылки, потому что увидел её.

   **Порог выбран асимметрией вреда, а не точностью.** Ложная блокировка
   сокращателя ломает все чужие ссылки у всех, кто поставил расширение; ложный
   пропуск вредит тому, кто перешёл по одной ссылке. Измерено до того, как
   написано: на 253 записях под правило попадают пять хостов, все пять —
   сокращатели, при медианной длине хоста 22.

   **Проверенная и отвергнутая гипотеза:** различать общий хост по числу
   различных путей в фиде. Не работает в обе стороны —
   `wells-fargo-ac06dd.previewship.net` встретился с 16 путями и это кампания на
   своём хосте, а сокращатель `g5.lu` встретился один раз.

## Цена

- **Покрытие узкое и это записано.** 248 хостов против 600k у агрегата. Продукт
  блокирует свежий фишинг и не претендует на большее; `docs/coverage-matrix.md`
  не отмечает 1.4, 1.5 и остальные векторы, которых этот источник не закрывает.
- **Список неполон по построению.** Новый сокращатель, длиннее восьми символов,
  пройдёт. Правило отвергает **и печатает** отвергнутое, поэтому день, когда
  отказов станет двадцать за прогон, — это день, когда источник сменил форму.
- **Один источник — одна точка отказа.** Упавший источник **останавливает
  прогон**, а не сокращает список: меньший фид с большей версией молча
  разблокировал бы всё, что из него выпало, и объявил бы это обновлением.

## Обновление — только с машины, и это не выбор этого решения

OpenPhish обновляется примерно раз в 12 часов. Автопубликация из CI **запрещена
[ADR-0002](0002-worker-never-signs.md)**: фид подписывается на машине, где лежит
приватный ключ, и перенос ключа в CI — ровно та сделка, от которой то решение
отказалось. Поэтому расписание может быть только локальным:

```bash
pnpm feed:refresh   # собрать и опубликовать, одной командой
```

Поставить по расписанию на этой машине (раз в 12 часов):

```bash
# launchd: ~/Library/LaunchAgents/app.okolos.feed.plist
# StartInterval 43200, ProgramArguments: /bin/sh -lc 'cd <repo> && pnpm feed:refresh'
```

Это остаётся человеческим шагом (B-25), потому что установка агента на чужую
машину — не то, что делает пайплайн. Один прогон ежесуточно лучше, чем ни
одного: список свежего фишинга стареет за часы, а не за недели.

## Чем держится

- `tools/ingest.test.ts` — 26 правил, включая `dropbox.com`, публичные суффиксы,
  голые IP, пять реальных сокращателей и запрет на подключение URLhaus,
  записанный **тестом**: пасс, который добавит его ради числа записей, должен
  будет удалить эту строку и прочитать, почему она там.
- `tools/ingest.mjs` — отвергнутое печатается всегда.
